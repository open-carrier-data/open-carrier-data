# Operator statements and the carrier-identity table

Written by the private publisher from the hand-checked operator statements lane (rule round 32). CC0-1.0.

- `statements.json`: what operators, brands and MVNOs state on their own pages about MMS, VoLTE, Wi-Fi calling at home and abroad, VoLTE roaming, eSIM, 5G SA and VoNR. Each statement names the page, the day it was read and the hash of the passage it rests on, with a paraphrase, never quoted text. A statement says what the operator sells, not what a tariff includes or a phone supports. Show it as "the operator states it offers X (read on <checked_at>); whether your tariff includes it is not checked", never as "works". Only a statement with `sets_value` true changes a value: an MMS end the operator states network-wide, checked by a second reader. Its networks' profiles publish `mms` `unsupported` and `enabledMMS` false from `operator_statement`. A statement not confirmed for 180 days, or not swept for 365, lapses to `unknown` with its `previous_status`. `mms_ended_networks` lists every network whose history holds an admitted network-wide MMS end, lapsed ones included.
- `carrier-identity.json`: which operators, brands and MVNOs run on which network codes, built from the sources' own labels (LineageOS APN carrier names, Samsung network names and sales codes, Google carrier ID names, Apple bundle names), with the SIM selectors exactly as a source states them and the OCD profile each maps to. A `host_only` brand has no selector any source states, so OCD does not tell its SIMs from the host's, though the SIM may still show a name: show it as a brand on that network, never as a statement about the SIM.
- `entities.json`: the identity table's entries as named things (migration step 5, rule round 47, item 4): networks with MCC and MNC as two fields and the holder the regulator lists, operators with their kind, and brands with dated `runs_on` links where a source was read. `vendor_names` records what the vendor lists call a network, with `agrees` false where that differs from the holder. A label for people: it changes no match, no value and no phone, and phones never read it.
- `sim-groups.json`: each profile the identity table reaches, with its brand or brands and `tellable`: `yes`, `ambiguous` or `no` (migration step 6). `tools/sim_groups.py` derives it, and validate compares it. A label for people: it changes no match, no value and no phone. OCD Android reads it for the plan picker only, and no carrier settings component reads it.
- `plan-families.json`: the plan families a SIM itself shows, from Android's child carrier IDs, as labels over the profiles that already state them (migration step 7). `tools/plan_families.py` derives it, and validate compares it. A plan family stays a selector in carrier data: never a new SIM group or a matching key, and phones never read this file.
- `offers.json`: dated tariffs, options and packs as the carrier's own pages name them, with feature states, and what a brand states for a feature with no named offer (migration step 8). A dated claim, never proof that a line has a feature: it feeds no `for_you` answer, no value and no match. No automatic report names a plan; only the person's tapped report may. OCD Android reads it for the plan picker only, and no carrier settings component reads it.

The public `tools/validate_operators.py` checks the files against `schemas/operator-statements.schema.json`, `schemas/carrier-identity.schema.json`, `schemas/operator-entities.schema.json` and `schemas/operator-offers.schema.json`, and every selector against the same prefix limits as every other published file.
